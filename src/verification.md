# IAK 스킬 재현 검증 · 2026-09-16

## 확인한 과정

공개 스킬 v0.10을 별도 프로젝트에 설치한 뒤 새 Claude Code 세션에 템플릿 URL과 자연어 요청을 전달했습니다. 기존 샘플 소스는 전달하지 않았습니다. React 19.2.8·TypeScript·Vite와 IAK UI 0.9.0을 사용한 로컬 결제 예제가 생성되었습니다. 예제 앱은 공개 배포하지 않았습니다.

## 최초 결과와 검수

최초 결과는 테스트 21개와 빌드가 통과했지만 테스트가 IAK 컴포넌트를 mock으로 대체했습니다. Codex 검수에서 미연동 결제·메일 발송 문구, 외부 폰트 중복 로드, 할인 Enter의 폼 제출, 오류·결과 포커스, 문서 언어·제목, 모바일 콘텐츠 순서를 수정했습니다. 실제 패키지를 사용하는 통합 테스트를 추가해 최종 22개 테스트와 빌드가 통과했습니다.

브라우저에서 빈 입력 오류, 첫 오류 포커스, 수량·할인 계산, 할인 Enter, 데모 실패 후 입력 유지와 재시도, 결과 제목 포커스를 확인했습니다. 1440px 데스크톱과 375px 모바일에서 배치와 가로 넘침을 확인했습니다. 가격·수량 제한 등 샘플 콘텐츠의 변경은 템플릿을 그대로 재현한 것으로 평가하지 않습니다.

## v0.11 반영

검수 결과를 스킬의 구현·완료 기준에 반영했습니다. 기존 IAK 디자인 자산과 UI/MCP 0.9.0은 유지합니다. 스킬 문법 검증은 실제 생성 품질 검증을 대신하지 않습니다.

## 남은 검증

- 추가 템플릿 및 여러 생성 세션의 반복 확인
- 다른 OS·브라우저와 실제 스크린리더 조합
- IAK 라이브러리 전체 React 19 호환성

생성 후 검수가 필요했던 사례입니다. 무검수 자동 완성이나 실제 결제·예약·메일 연동을 보장하지 않습니다.

## 추가 적용: Project Workspace · v0.11

Codex가 v0.11 스킬과 공개 프로젝트 템플릿으로 별도 React 18 앱을 구현했습니다. 현재 대화 맥락을 가진 구현·검수이며 새 AI 세션의 독립 평가는 아닙니다. 검색, 상태 필터, 정렬, 생성, 카드 상세, 이름 변경, 복제, 보관·복원과 브라우저 저장을 연결했습니다.

실제 IAK UI 패키지를 사용하는 테스트를 포함한 6개 테스트와 타입 검사·빌드가 통과했습니다. 브라우저에서 데이터 변경 및 새로고침 유지, 1440px 3열/375px 1열, 키보드 대화상자와 모바일 메뉴를 확인했습니다. 검수 중 모바일 메뉴 및 공유 대화상자의 포커스 복귀를 앱에서 보완했습니다. 원본 디자인 자산과 UI 패키지는 변경하지 않았습니다. 예제는 로컬에만 있습니다.

결제 템플릿에만 해당하는 데모 결제·할인 Enter 조건을 이번 프로젝트 화면으로 재검증한 것은 아닙니다. 아래에 새 Claude 세션과 추가 브라우저의 후속 결과를 기록합니다.

## Chrome 교차 검증

기존 Codex Project Workspace 예제를 Chrome 153.0.8010.48(macOS)에서 추가 확인했습니다. 생성·필수 입력·Enter·이름 변경·복제·보관·복원·새로고침 유지, 검색·필터·정렬, 1440px 3열과 375px 1열 및 키보드 포커스 흐름을 확인했습니다. 사용자 브라우저 확장 프로그램이 있는 환경이며 깨끗한 프로필의 네트워크 검증을 뜻하지 않습니다.

첫 Claude v0.11 시도는 생성 전 실행 한도로 중단됐고 첫 Safari 시도는 제어 시간 초과였습니다. 아래 재시도로 결과를 갱신합니다.

## 새 Claude v0.11 재시도 · Project Workspace

공개 스킬을 별도 프로젝트에 설치하고 새 Claude Code 2.1.185 세션에 템플릿 URL과 자연어 요구사항을 전달했습니다. 기존 예제 코드는 전달하지 않았습니다. React 18·IAK UI 0.9.0 앱을 생성했으며 최초 테스트 14개와 빌드가 통과했습니다.

브라우저 검수에서 보관함 사이드바 미연결, 상세창 포커스 미이동, Esc 닫기 누락을 발견했습니다. 원본을 보존하고 실제 IAK 컴포넌트를 사용하는 수용 테스트 3개의 실패를 확인한 뒤 Codex가 수정했습니다. 수정 후 테스트 17개와 타입 검사·빌드가 통과했습니다. 카드 열기 버튼과 메뉴를 분리하고 동작하지 않는 즐겨찾기 메뉴도 제거했습니다.

앱 내 브라우저에서 생성·수정·복제·보관·복원·저장 유지, Chrome에서 생성·검색·필터·저장 유지와 375px 배치를 확인했습니다. 수정 후 두 브라우저에서 보관함, 상세창 Enter 진입·포커스·Esc·카드 포커스 복귀를 재확인했습니다. 모바일 상세창은 375px 문서 안에 표시됩니다. 생성 앱은 로컬에만 있으며 원본 IAK 자산과 UI 패키지는 유지했습니다.

최초 생성만으로 완료된 사례가 아닙니다. Claude 앱의 Safari/Firefox, 실제 스크린리더, 저장 실패·손상 복구, 다른 OS는 미검증입니다.

## Safari 재시도 성공 · 2026-09-16

Safari 26.5.2(macOS)에서 기존 Codex 앱의 빈 이름 오류·Enter 생성·이름 변경·복제·보관·복원·새로고침 유지·검색 0건·완료 상태 필터를 확인했습니다. Option+Tab으로 카드에 접근해 Enter로 상세창을 열고 Esc로 닫힌 후 카드 포커스 복귀를 확인했습니다. 브라우저 설정은 바꾸지 않았습니다. Safari 모바일 화면 및 스크린리더 감사는 수행하지 않았습니다. 새 Claude 앱의 검증과 별개입니다.

## 접근성 구조·키보드 추가 점검 · 2026-09-16

axe-core를 jsdom에서 실행해 목록, 생성 폼 오류 상태, 상세 Dialog를 점검했습니다. h1 다음 h3로 건너뛰던 카드 제목을 h2로 수정했습니다. 카드 메뉴의 접근 가능한 이름에 프로젝트 이름을 포함했고, 생성 폼 이름 입력에 required를 추가했습니다. IAK 색상·폰트·컴포넌트 패키지는 유지합니다.

실제 IAK 컴포넌트를 사용하는 오류 설명 연결·첫 오류 포커스, 상세 Dialog의 Tab/Shift+Tab 순환·Esc 후 카드 복귀 테스트를 추가했습니다. 총 19개 테스트와 타입 검사·빌드가 통과했습니다. 앱 내 브라우저에서도 빈 이름 Enter 제출 후 오류·포커스, 상세창의 Tab 6회/Shift+Tab 6회 내부 유지와 Esc 닫기를 확인했습니다.

기존 개발용 Vitest 2를 호환 가능한 4.1.11로 갱신했습니다. 갱신 후 npm audit 기준 알려진 취약점은 0개입니다.

자동 구조 검사에서 color-contrast는 jsdom의 레이아웃 한계 때문에 제외했습니다. 색 대비 전체 감사, 실제 VoiceOver/NVDA 음성 출력, Windows/다른 OS 검증을 완료했다는 뜻은 아닙니다. 다음 실제 보조 기술 검수에서는 메뉴 이름 구분, 오류 문구 읽기, 모달 제목 안내, 포커스 복귀를 확인해야 합니다.
