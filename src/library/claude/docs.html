Design Rulebook

Five non-negotiables, visual DNA, and the do / don't that frames every screen review.

The five non-negotiables
One accent
Orange (#FFA726) is the only system accent. Blue is a data role, never a brand colour.
Pretendard only
No Roboto / Barlow / Public Sans. Korean, English and numerals share one face.
Focus signal
1 px accent border + inset 1 px ring. Never an outer halo or bloom.
State expression
Colour + text + icon together. Never colour alone (WCAG 1.4.1).
Brand split
Gem mark = identity (sidebar / topbar). Chrome motif = decorative (hero / header). They never share a composition.
Visual DNA
Surface stack
canvas #0D0D0D → elevated #121212 → card #0D0D0D → card-alt #161616 → field #1C222B
Border
rgba(145,158,171, 0.08–0.20) only — no solid hex borders
Glow
Resting decoration under coloured plates. Tight, ≤ 24 % opacity. Never as focus.
Density
4 px base. Card padding 24 · section gap 32 · page padding 32
Radius
Buttons / inputs md (8) · mid card xl (16) · primary card 2xl (24) · pill 500
Do / Don't
Do
  • Use semantic tokens (color/action/primary/default).
  • Apply text-wrap: pretty and font-feature-settings: "tnum" on numerics.
  • One primary CTA per surface.
  • Pair every status colour with text and an icon.
  • Render the gem logo as a flat raster on the canvas.
Don't
  • Drop raw hexes into product code.
  • Bold body copy for emphasis — use a chip or label.
  • Stack two filled-orange buttons next to each other.
  • Communicate state with colour alone.
  • Apply glow / halo / drop-shadow / blue-bg to the gem.
Token reference
  • tokens/colors.json — semantic colour roles + states
  • tokens/typography.json — type roles
  • tokens/spacing.json — spacing, radius, shadow, glow, focus
  • colors_and_type.css — runtime CSS custom properties (the source of truth at runtime)

Auto-layout rules (Figma + JSX parity)
  • Every component is hug × hug unless explicitly fixed-width.
  • Padding lives on the parent, never on children via margin.
  • Gap is the only inter-child spacing — no padding-fakes.
  • Icons resize via fixed pixel size, never by stretching.
  • Text containers wrap with text-wrap: pretty.
02

State System

Twelve states for every interactive component. Each state expressed by colour + text + icon — never colour alone.

The twelve states
Default
bg surface/card · border border/default · icon text/secondary · text text/primary · CTA available
Hover
bg +6 % brightness · border border/strong · icon → text/strong · cursor pointer
Pressed
bg action/primary/pressed · border border/strong · text text/strong
Focused
unchanged bg · border focus 1 px + inset 1 px ring · tabindex visible
Selected
bg surface/selected (#FFA726 @ 10 %) · left-rule accent 2 px · icon accent · persistent
Loading
unchanged bg + border · replace icon with 18 px spinner · text text/secondary · CTA disabled
Skeleton
bg surface/elevated shimmer · no border · placeholder bars · CTA hidden
Empty
bg surface/elevated · dashed border/default · illustration / Eva outline · primary CTA "Add first…"
Success
bg status/success @ 8 % · border status/success 1 px · icon eva:checkmark-circle-2-fill · CTA "Continue"
Warning
bg status/warning @ 8 % · border status/warning 1 px · icon eva:alert-triangle-fill · CTA "Review"
Error
bg status/error @ 8 % · border status/error 1 px · icon eva:close-circle-fill · CTA "Retry"
Disabled
bg surface/card · border border/subtle · text text/disabled · opacity 0.6 · cursor not-allowed
Animation specs
Hover
background, border-color · 120 ms · ease-out
Focus
box-shadow, border-color · 0 ms · instant for accessibility
Pressed
transform scale(0.98) · 80 ms · ease-in
Loading spinner
rotate 360° · 800 ms · linear, infinite
Skeleton shimmer
gradient sweep · 1500 ms · linear, infinite
Toast in / out
translateY + opacity · 200 / 160 ms · cubic-bezier(0.2,0.8,0.2,1)
Accessibility floor
  • Contrast: every text + bg pair must clear WCAG AA 4.5:1 (3:1 for ≥ 18 px).
  • Focus must be keyboard-visible without a mouse hover.
  • Status colours always paired with an icon for users who can't perceive hue.
  • Click targets ≥ 44 × 44 px on touch surfaces.
Naming for AI prompts
Pattern: State / Role / Component / State
  • State / Action / Button / Pressed
  • State / Status / Toast / Error
  • State / Field / Input / Focused
  • State / Empty / Card / Default

The ten templates
1 · Dashboard
Sidebar + Topbar · Page-head · Metric row-4 · Panel row-2. Reference: ui_kits/rais-dashboard/index.html
2 · Analytics
Same shell as Dashboard. Replaces row-2 with chart + filter rail. Header may host a chrome-motif analytics-header (right-aligned, cropped).
3 · Table
Page-head → filter chip-rail → bulk-action bar (when rows selected) → table → footer pager. Cell padding 12 × 16.
4 · Detail
Page-head → primary card (Hero / Identity) → tabbed sub-pages → activity feed in side rail.
5 · Settings
2-col within content: nav rail (200 px) left, form column right. Section gap 32 · form-row gap 16 · label above input.
6 · Billing
Settings shell + Card / Plan / Highlighted for current plan + Table / Invoices.
7 · AI Chat
2-col: conversation list (240 px) left, message thread right. Composer sticky bottom · 56 px tall · surface/field.
8 · Builder
3-col: node palette (240 px) · canvas (fluid) · inspector (320 px). Canvas uses surface/elevated with 24 px dot grid at border/subtle.
9 · Modal
Width sm 480 · md 640 · lg 880. Padding 24 · radius xl (16) · shadow shadow-floating · backdrop surface/overlay. Close eva:close-fill 20 px top-right.
10 · Empty
Centred. Illustration / icon (96 px) → headline (type/section/title) → sub (type/body/md) → primary CTA. Container has border-dashed + surface/elevated.
Sectioning & responsive rules
Sectioning
  • A section = overline + section title + optional helper + content.
  • Wrap related cards in a single section to allow consistent gap.
  • Two consecutive sections are separated by section-gap (32). No extra dividers.
  • Page-head is always the first section, never wrapped in a card.
Responsive behaviour
≥ 1440
Full sidebar · 12-col grid
1280–1440
Collapse sidebar to 240 px
960–1280
Collapse sidebar to icon-only (72 px)
640–960
Sidebar becomes top drawer · metric row-4 → row-2
< 640
Single column · cards stack · tables horizontal-scroll inside their card
04

Screen QA Checklist

Run before every handoff. A screen is not done until every item clears.

Layout
  • Page padding = 32 · section gap = 32 · card gap = 16
  • No off-grid spacing (every gap maps to a spacing/* token)
  • Sidebar 280 px (default) · topbar 64 px
  • Single primary CTA per surface
  • Card radius matches role (xl 16 mid · 2xl 24 primary)
Typography
  • Pretendard only — no Roboto / Barlow / Public Sans
  • Page title uses type/page/title · section titles use type/section/title
  • Numeric columns use font-feature-settings: "tnum"
  • No font sizes below 12 px in product UI
  • No bolding for emphasis in body — use a chip or label
Component
  • Buttons render correct padding for size (Md 8 × 14)
  • Inputs use surface/field bg · md radius
  • Toast icon plate is rounded-square (8 px radius), not circle
  • Badge uses pill radius and status/{role} @ 14 % bg
  • Icons all from a single family (Eva / Solar solid)
  • No icon family mixing within a screen
State
  • Hover state defined for every clickable element
  • Focus = border + inset ring (no outer halo)
  • Loading + skeleton state defined where data is async
  • Empty state defined with illustration + primary CTA
  • Error state pairs colour + text + icon
Accessibility & Brand
Accessibility
  • All text passes WCAG AA contrast on its surface
  • Status communicated by colour + icon + text
  • Keyboard focus visible without mouse hover
  • Hit targets ≥ 44 × 44 on touch
  • All images have alt · decorative motifs have aria-hidden="true"
Brand
  • Gem logo only in sidebar / topbar / identity (never as hero)
  • Chrome motif only in hero / analytics header / promo (never as logo)
  • Logo and motif never appear in the same composition
  • No glow / halo / blue-bg on the gem mark
Responsive
  • Sidebar collapses correctly at 1280 / 960 / 640
  • Metric row-4 reflows to row-2 then row-1
  • Tables become horizontal-scroll inside their card on mobile
  • Modal becomes full-screen sheet at < 640

Output format rules & what NOT to ask
Output rules
  • HTML output references colors_and_type.css only — no inline hexes.
  • JSON output uses token paths, never literal values.
  • Markdown output uses sentence-case, single-line cells.
  • All component examples include the state field, even if Default.
Never ask Claude to
  • Invent a new accent colour.
  • Add an outer glow as focus.
  • Mix icon families.
  • Use the gem mark as a hero image.
  • Bulk-replace tokens — they are versioned in tokens/*.json.
