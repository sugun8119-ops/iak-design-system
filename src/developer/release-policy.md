# IAK 패키지 릴리스·호환성 정책

IAK UI는 아직 0.x Preview입니다. 모든 제품에서 검증된 안정 버전이라는 의미는 아닙니다.

## 설치와 업데이트

- UI 0.9.1: Dialog initialFocusRef에 React 19의 nullable ref 타입을 허용합니다. 시각 토큰·컴포넌트 동작은 바꾸지 않습니다.
- MCP 0.9.1: UI 설치 주소와 호환성 안내를 갱신합니다.
- 사이트/스킬 0.12.0: 새 패키지 설치 주소를 안내합니다. 기존 앱 의존성을 자동으로 변경하지 않습니다.
- 앱마다 정확한 tarball URL과 lockfile을 보관하세요. 업데이트는 별도 브랜치에서 앱의 테스트·빌드·주요 화면을 확인한 뒤 적용합니다.
- 문제가 있으면 이전 tarball URL로 설치하고 해당 lockfile로 되돌립니다. UI/MCP 0.9.0 파일은 기존 공개 주소와 동일한 바이트로 보존합니다. 더 오래된 버전까지 보존했다고 보장하지 않습니다.

## 변경 기준

- patch: 기존 호출과 디자인을 유지하는 결함·타입 수정.
- minor: 호환 가능한 컴포넌트·선택적 props 추가. 0.x에서 호환 불가 변경이 필요한 경우에도 minor를 올리고 마이그레이션을 명시합니다.
- 삭제/이름 변경/기본 동작 변경은 릴리스 노트와 대체 예제 없이 적용하지 않습니다. 가능하면 먼저 deprecated 기간을 둡니다.
- 이미 공개한 버전 URL의 파일을 수정하지 않습니다. 변경 내용은 새 버전으로 배포합니다.

## 배포 관문

1. 패키지 빌드, 기존 기능 테스트, 자산 보존·설치기·MCP 검사.
2. 빌드한 tarball을 실제 설치: Linux/Windows/macOS × React 18/19, Node 22.
3. 공개 export 목록, CSS/폰트/타입 포함 여부, 실제 설치 패키지의 UI 동작, TypeScript 소비자 사용 예제를 검사.
4. 위 소비자 CI가 실패하면 Pages 배포를 시작하지 않습니다.
5. 기존 UI 화면과 모바일·키보드 검수는 별도로 수행합니다. jsdom 통과를 실제 브라우저나 스크린리더 인증으로 표현하지 않습니다.

GitHub Actions의 Deploy Pages 결과에 각 조합의 결과가 표시됩니다. 이 정책은 미래의 API 변경을 모든 경우에 자동 감지하지는 않습니다. 새로운 사용 사례마다 소비자 예제와 동작 검사를 추가해야 합니다.
